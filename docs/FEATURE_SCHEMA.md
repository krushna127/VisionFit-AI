# VisionFit-AI Feature Schema

## 1. Purpose

This document describes the data generated by the computer vision (CV) module of VisionFit-AI. It explains how body landmarks and joint angles are stored so that other modules can use the data without confusion.

The CV module processes workout videos, detects body landmarks, and calculates joint angles. The outputs are then used by the other team members for exercise classification, repetition counting, and form analysis.

## 2. Input Video

The current test video is `samples/squats.mp4`.

| Property | Value |
|---|---|
| Duration | Approximately 7.4 seconds |
| Frame rate | 30 FPS |
| Frame count | 222 |
| Resolution | 1920 × 1080 |

These values describe the sample video used for testing. Other input videos may have different properties.

## 3. Pose Landmark Output

**Output file:** `runs/pose/squats_keypoints.csv`

Each row in this file represents one frame from the video. It contains information about the frame and the body landmarks detected by the model.

### Frame metadata

| Field | Description |
|---|---|
| `frame_index` | Frame number, starting from zero |
| `timestamp_ms` | Timestamp of the frame in milliseconds |
| `image_width` | Width of the original frame in pixels |
| `image_height` | Height of the original frame in pixels |
| `person_detected` | Indicates whether a person was detected in the frame |

### Landmark fields

For each body landmark, the file stores three values:

- `<landmark>_x`: horizontal position in pixels
- `<landmark>_y`: vertical position in pixels
- `<landmark>_confidence`: confidence score assigned by the model

The top-left corner of the image is used as the coordinate origin. The x-coordinate increases towards the right, while the y-coordinate increases downwards.

### Fixed landmark order

The model provides 17 body landmarks in the following fixed order:

1. `nose`
2. `left_eye`
3. `right_eye`
4. `left_ear`
5. `right_ear`
6. `left_shoulder`
7. `right_shoulder`
8. `left_elbow`
9. `right_elbow`
10. `left_wrist`
11. `right_wrist`
12. `left_hip`
13. `right_hip`
14. `left_knee`
15. `right_knee`
16. `left_ankle`
17. `right_ankle`

Confidence scores range from 0 to 1 and indicate how confident the model is about a detected landmark. A high confidence score does not always guarantee that the landmark is positioned accurately.

## 4. Joint-Angle Feature Output

**Output file:** `runs/pose/squats_joint_angles.csv`

This file stores the calculated joint angles for each video frame. It includes the frame index, timestamp, and six angle features.

| Field | Description |
|---|---|
| `left_knee_angle_deg` | Left knee angle in degrees |
| `right_knee_angle_deg` | Right knee angle in degrees |
| `left_hip_angle_deg` | Left hip angle in degrees |
| `right_hip_angle_deg` | Right hip angle in degrees |
| `left_elbow_angle_deg` | Left elbow angle in degrees |
| `right_elbow_angle_deg` | Right elbow angle in degrees |

Each angle is calculated using three body landmarks, with the middle landmark acting as the vertex. The angles are measured in degrees using 2D image coordinates, so they should not be treated as exact 3D anatomical measurements.

## 5. Missing and Invalid Data

The current joint-angle exporter uses a confidence threshold of `0.25` to filter out unreliable landmarks.

A landmark is rejected if its coordinates or confidence score are missing, malformed, non-finite, outside the valid confidence range of 0–1, or below the threshold.

If a required landmark is rejected, the corresponding joint angle cannot be calculated. In such cases, the angle is stored as a blank value in the output CSV file.

**A blank angle must not be treated as zero degrees.** Other modules should preserve missing values and use `frame_index` and `timestamp_ms` to match the data with the correct video frame.

The original landmark coordinates and confidence scores remain available in the keypoint CSV file for further inspection.

## 6. Limitations and Scope

- The pipeline uses pretrained YOLO11-Pose weights. Training a custom pose model is outside the scope of the initial MVP.
- The current implementation assumes that one primary person is present in the video.
- Testing has been carried out using a squat sample video. More testing is needed with different exercises and recording conditions.
- Camera angle, body orientation, occlusion, and perspective can affect landmark detection and joint-angle accuracy.
- The CV module provides landmarks and joint-angle features. Exercise classification, repetition counting, and form evaluation are handled by separate modules.

## 7. Integration Notes

- Use `frame_index` and `timestamp_ms` to match data between output files and video frames.
- Keep landmark names, feature-column names, and angle units consistent when integrating other modules.
- Handle blank or missing angle values explicitly instead of treating them as zero.
- The confidence threshold can be adjusted when needed, but changes should be communicated to the team.
- Discuss schema changes with the team before changing field names, data formats, or units.
